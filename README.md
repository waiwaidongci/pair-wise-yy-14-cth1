# 雁迹环志数据校验与移交工具

用于汇总多年、多来源的鸟类环志记录，执行环号与鸟种归一化、跨年重复检查、坐标格式转换和地点异常跳变分析。支持规则批量修正、逐条接受或退回、操作历史回滚，并导出区域环志中心要求的 CSV 与 JSON。

新增「回执对账」页（`/reconcile`）把**移交批次、审核回执、处置记录**三方接成对账：

- 回执按 **中心记录号 + 本地环号 + 观察时间** 三方匹配；对不上的（记录号不存在、环号身份不符、时间不符、记录号重复）只列入挂起清单，**不改任何记录**，人工核对销项后才允许带回下一批。
- 中心对环号的归一化（如去分隔符的 `BJ202101234`）只用于呈现比对：身份一致、写法不同登记为呈现差异，**绝不采信覆盖**本地人工结论。
- 判**通过**的记录按提交瞬间本地值**冻结**；之后本地后到更正不动定稿，只登记字段差异。判**退**则按中心原因把已处置问题**重开**（保留重开前状态）；后续回执改判通过时自动还原。
- **同一份回执只算一次**：同编号同版本的重发副本幂等跳过；签发时间更早的晚到旧件整份拦截，不倒退任何状态（以回执签发时间为准，不依赖版本号大小）。
- 缺回执编号的历史导入数据，按批次登记的**初始回执**统一回填编号。
- 台账写入走「**先落恢复日志、再提交台账**」：写入失败时记录零改动，可从已对上记录的日志重放恢复；恢复本身也只算一次。
- 每次回执更新后，**待移交清单按新结果重算**：冻结的剔除，判退处置完的带回，未见结论的等回执，挂起的留原批。
- 移交定稿与回执动作是锁定审计记录，不允许回滚覆盖。

规则引擎在 `src/utils/reconciliation.ts`（纯函数），`scripts/reconcile-check.ts` 是可执行的对账规则断言（`node_modules/.bin/esbuild` 打包后用 node 运行）。

```bash
corepack pnpm install
corepack pnpm dev
corepack pnpm build
```

所有数据均为浏览器内置模拟数据，不会上传到外部服务。
